# S15 · Web CMS

**Status:** implemented · **Fidelity:** new screens in the web app, plus one option for `create-admin`.
Depends on S11, S12, S13 and S14. Its look is the [Tinta design system](design-system.md).

## Goal
Administrators manage the feeds from the web app: they log in, browse every feed, create, edit,
recategorize and delete feeds, and refresh the newspapers' front pages, with a session that survives
a page reload and ends cleanly when the token expires.

## Session

### `/login`
- Email and password fields and an *Entrar* button. The page shows the brand panel of the canvas next
  to the form on wide screens; on narrow screens only the form.
- Success stores the token in **`sessionStorage`**: it survives a page reload and is forgotten when
  the tab is closed; each tab logs in on its own.
- 401 → *Email o contraseña incorrectos*, the same for an unknown email and a wrong password (S11).
  A 400 (a missing field) is prevented by the form: both fields are required.
- The page receives where to return (`/login?redirect=/admin/feeds/…/edit`) and goes there after
  logging in, else to `/admin`. Only paths of the app that start with `/` and not `//` are accepted;
  anything else goes to `/admin`.
- An administrator with a valid session who opens `/login` goes to `/admin`.

### Lifecycle
- On start, with a stored token the app calls `GET /auth/me` (S13): 200 restores the session; 401
  forgets the token.
- The session ends at `token_expires_at`: the app forgets the token and sends the user to `/login`
  with the current page as `redirect`, before a write can fail.
- Any 401 from the API during a session ends it the same way.
- *Cerrar sesión* forgets the token and goes to the front page; there is no logout route (S11).
- Every `/admin` route requires a session; without one it redirects to `/login` with `redirect`.
- The token is sent only as `Authorization: Bearer` to the API and is never logged or put in a URL.
- The reader header shows *Acceder* without a session and *CMS* with one.

## Layout
- A 240 px side menu with the brand and *CMS* label, *Noticias*, *Ver el sitio*, and at the bottom the
  administrator's email, *Sesión hasta las HH:MM* (from `token_expires_at`) and *Cerrar sesión*. On
  narrow screens it stacks above the content.
- The CMS uses the `canvas` background and `surface` panels (design system).

## Screens

### `/admin` · Feeds
- Title *Noticias* and two actions: *Actualizar portadas* (secondary) and *Nueva noticia* (primary).
- Filters as in `/feeds` (S14): words, category and newspaper, in the URL search params.
- A table in a horizontally scrollable panel: headline (links to the reader detail), newspaper,
  category, date, and actions *Editar* and *Borrar* as icon buttons with labels for screen readers.
- Pages of 20 with *Cargar más* (S12).
- *Actualizar portadas* calls `GET /feed/scrap`, shows *Actualizando…* and disables itself while the
  run lasts, then shows *Portadas actualizadas: N noticias nuevas* (or *No hay noticias nuevas*) and
  refreshes the list and the front page.

### `/admin/feeds/new` · Create
- Fields: title, description (optional), author, and category as chips with their markers.
- The app checks the fields before sending, with Spanish messages: a blank title, a blank author, no
  category.
- The id is generated by the app with `crypto.randomUUID()` and sent with `PUT /feed/{id}`.
- A preview card *Así se verá en la portada* shows the feed as a reader card while it is typed.
- 201 → `/admin` with the notice *Noticia creada*. 409 (an id already taken) is an unexpected error:
  the form keeps its values and shows *No se pudo guardar la noticia*.

### `/admin/feeds/$id/edit` · Edit
- The same form, prefilled. The author, newspaper and original link are shown read-only with *El
  autor, el periódico y el enlace no se pueden cambiar* (S04, S09).
- `PATCH` sends only the fields that changed; emptying the description sends `null`. With no change
  *Guardar cambios* is disabled.
- Scraped feeds can be edited and recategorized too (S09).
- 200 → `/admin` with the notice *Cambios guardados*. 404 → *Esta noticia ya no existe* and back to
  `/admin`.
- Leaving the form with unsaved changes asks for confirmation.

### Delete
- From the list or the edit form, after a dialog *¿Borrar esta noticia?* that shows the title and
  says it cannot be undone. The confirm button is the destructive variant.
- 204 or 404 both end with the feed gone from the list and the notice *Noticia borrada*.

## Errors
- Validation the app already checks never reaches the API. Any other 400, or a 500, shows *No se pudo
  guardar la noticia* (or the action's equivalent) with the API message as detail; the form keeps its
  values.
- Writes are never retried automatically.

## `create-admin` for scripts
- `uv run daily-trends-py create-admin --email <email> --password-stdin` reads the password once from
  standard input (until the end of the first line) instead of asking twice with `getpass`. The rest of
  S11 applies: the same validation, messages and exit codes; the password is never printed.
- Without `--password-stdin` the command behaves as in S11.
- It is what the end-to-end setup and local scripts use to create an administrator.

## End-to-end tests
- The S14 harness creates an administrator with test credentials from the E2E fixtures through
  `create-admin --password-stdin`.
- Scenarios: logging in with wrong and right credentials; creating a feed and finding it on `/feeds`;
  editing its title and category; deleting it; an expired session (a short `AUTH_TOKEN_TTL_SECONDS`)
  sends the user to `/login` and back to the page after logging in; `/admin` without a session goes
  to `/login`.
- *Actualizar portadas* is covered by component tests with MSW, never end to end (S14).

## Out of scope
Managing administrators from the web, password reset, refresh tokens, roles, editing several feeds
at once, undo, drafts, and an activity log.

## Edge cases
- Two tabs: logging out in one does not log out the other (`sessionStorage`).
- The token expires while the edit form is open → the session ends, the user logs in, and returns to
  the form, which reloads the feed; unsaved changes are lost, and the confirmation before leaving does
  not block the expiry.
- `/login?redirect=https://evil.example` or `//evil.example` → after logging in, `/admin`.
- *Actualizar portadas* while a scheduled run is in progress (S10, once implemented) → the button
  waits for the response like any other run.
- A feed deleted by another administrator while its edit form is open → saving answers 404 and the
  form says it no longer exists.

## Acceptance criteria
- Component tests with MSW: the login errors and the redirect rules; restoring the session with
  `/auth/me`; ending it at `token_expires_at` and on a 401; the route guard; the list with filters and
  pages; create (validation, generated id, preview, 201, 409); edit (only changed fields, `null`
  description, disabled save, 404, the leave confirmation); delete (dialog, 204, 404); the scrape
  states and messages.
- CLI tests for `create-admin --password-stdin`: success, a short password, an invalid email and a
  duplicate, with the exit codes of S11, and the password never printed.
- The end-to-end scenarios above pass in CI.
- `S00` lists S15; `README.md` explains how to create an administrator and open the CMS.
- The quality gates of `AGENTS.md` and S14 pass.
